How I try to work

Keep the basics
visible.

A good-looking page is useful only if the repository is readable too. Where it makes sense, I leave setup steps, tests, a simple comparison, and a note about what the project should not be used for.

01 · Run it

Start with instructions that let another student reproduce a small result.

02 · Compare it

Use a baseline when a model claim needs context.

03 · Explain it

Write down the input, assumptions, and the failure case I noticed.

04 · Keep it small

Add an API or demo only when it makes the idea easier to inspect.
